# Vendored cmark-gfm

The C library under `src/cmark/` and `src/extensions/` is a copy of
[cmark-gfm](https://github.com/github/cmark-gfm), the GitHub fork of John
MacFarlane's [cmark](https://github.com/commonmark/cmark) reference
implementation of CommonMark. litedown calls this library directly (instead of
depending on the [commonmark R package](https://github.com/r-lib/commonmark)) so
that bugs can be fixed and features added at the C level rather than worked
around in R.

- Upstream cmark-gfm version: **0.29.0.gfm.9**
  (see `src/cmark/cmark-gfm_version.h`).
- License: BSD-2-clause, see `src/cmark/COPYING`.

## Files not from upstream cmark-gfm

These are litedown's own glue / bindings or are generated; `sync.sh` does not
overwrite them with upstream `src/` files:

- `src/init.c`       — native routine registration (`R_init_litedown`).
- `src/wrapper.c`    — `R_render_markdown()`, renders to a string. Adapted from
  the commonmark package.
- `src/extensions.c` — `R_list_extensions()`. Adapted from the commonmark package.
- `src/parse.c`      — `R_parse_markdown()` (parse tree as a nested list),
  `R_code_tokens()` (flat table of code blocks / inline code), and
  `R_prose_lines()` (indices of lines not inside a code block, replacing
  `xfun::prose_index()`). Written for litedown.
- `src/extensions/litedown-extensions.c` / `.h` — registration of litedown's own
  cmark syntax extensions (kept separate from upstream's `core-extensions.c`,
  which `sync.sh` overwrites). Written for litedown.
- `src/extensions/math.c` / `.h` — LaTeX math extension (`$...$`, `$$...$$`, and
  `\begin{}...\end{}` environments). Written for litedown.
- `src/extensions/subsup.c` / `.h` — superscript (`^x^`), subscript (`~x~`), and
  strikethrough (`~~x~~`) extensions. The subscript extension owns `~` and
  provides both subscript and strikethrough (a delimiter char can belong to only
  one extension), toggled independently via private `LITEDOWN_OPT_*` option bits
  set in `wrapper.c` / `parse.c` through `litedown_attach_extension()`. The
  upstream `strikethrough` extension is therefore never attached. Written for
  litedown.
- `src/extensions/rawblock.c` / `.h` — raw content block extension
  (```` ```{=html} ````, ```` ```{=latex} ````, ```` ```{=tex} ````): a
  postprocess pass tags the matching code blocks with the extension so its
  render funcs emit the body verbatim into the matching output format (raw HTML
  in HTML, raw LaTeX in LaTeX) and discard it elsewhere. A raw LaTeX/TeX math
  environment is also rendered (wrapped in `<p>...</p>`) in HTML. Written for
  litedown.
- `src/Makevars`     — build rules (adapted from the commonmark package).
- `src/cmark/COPYING` — upstream license text.
- Generated by `sync.sh` (upstream builds these with CMake, which litedown does
  not use): `src/cmark/config.h`, `src/cmark/cmark-gfm_version.h`,
  `src/cmark/cmark-gfm_export.h`,
  `src/extensions/cmark-gfm-extensions_export.h`.

## Local patches

Local modifications to the vendored C are kept as diffs here and are **already
applied** to the committed sources (so a plain checkout builds without running
anything). The diffs are retained so they can be re-applied after syncing with a
newer upstream, and so they can be submitted upstream. `apply.sh` applies them
with `patch -p1` relative to `src/`; patch paths use the form `a/cmark/FILE` and
`a/extensions/FILE`.

Current patches (see `apply.sh`):

- `362.diff`             — GFM PR #362: expose footnote ids in XML/HTML
  (from upstream cmark-gfm, not yet merged).
- `latex-footnotes.diff` — commonmark PR #32: LaTeX footnotes via
  `\footnotemark` / `\footnotetext`.
- `inline-sourcepos-cols.diff` — litedown: fix inline source positions
  (columns / end lines) on indented continuation lines. To be submitted
  upstream to github/cmark-gfm.
- `html-block-code-fence-end.diff` — litedown: end a type 6/7 HTML block at an
  opening code fence, so `</p>` followed by a ```` ``` ```` line parses as an
  HTML block plus a separate code block (rather than the fence being absorbed
  into the HTML block). To be submitted upstream to github/cmark-gfm.
- `tasklist-no-disable.diff` — litedown: render task list checkboxes without the
  `disabled=""` attribute so they are interactive. litedown-specific (GitHub
  renders task lists as disabled), not intended for upstream.

Prefer adding new features as standalone files under `src/extensions/` rather
than as patches to core files: extensions survive upstream syncs untouched,
while patches are merge-conflict debt. Reserve patches for changes that must
touch core parser files, and file them upstream first when possible.

## Syncing with a newer upstream

Run the sync script from the package root:

```sh
src/patches/sync.sh          # latest release tag
src/patches/sync.sh REF      # a specific tag/branch/commit
```

It clones upstream at the given ref, copies the C sources into `src/cmark` and
`src/extensions` (dropping `main.c`), regenerates the CMake-produced headers
listed above, and re-applies the patches via `apply.sh`. After running it:

1. Build the package and run the tests (`R CMD INSTALL .` then
   `Rscript -e 'testit::test_pkg("litedown","test-cran")'`), and re-render the
   examples (`cd examples && CI=true Rscript _run.R`) to check for output
   changes.
2. If a patch no longer applies, fix it (or drop it if merged upstream) and
   regenerate its diff.
3. Update the version number at the top of this file.

This is automated by `.github/workflows/sync-cmark.yaml`, which runs monthly and
opens a pull request when the vendored sources change.
